# Is where you live actually boring?

If a city has things to do, it isn't boring: the people are. This project tests that by compiling a
long list of hobbies, crafts, sports and pastimes (299 activities), then checking which ones can
actually be done in each city, with how, where, cost and distance. Cities so far: Singapore, Hong
Kong, Tokyo, London, New York, Atlanta, Sydney, Paris, Chicago, San Francisco, Dubai, Shanghai and
Beijing.

This folder lives inside the blog repo. It holds the data and the scripts; the interactive explorer
they generate is the blog's `assets/boring-cities/` folder (one level up), drawn into the post by
`_includes/boring-cities.liquid`. The post is `_posts/2026-10-11-is-where-you-live-actually-boring.md`;
there is no standalone page. Jekyll does not publish this folder (it is in `exclude` in `_config.yml`).

To rebuild the explorer's data after changing anything here, from the blog repo root:

```sh
uv run boring-cities/scripts/build.py
```

## Layout

All the data is a handful of CSVs. Tables that differ by city have a `city` column first; `research`
and `not_found` also have a `batch` column saying which research round a row came from.

```
data/
  research.csv         the evidence: one row per city and activity (17 columns, see SCHEMA.md) + city, batch
  not_found.csv        activities searched for without finding a venue: city, batch, id, note
  curation.csv         audited manual drops and edits applied on top of research.csv
  cities.csv           city id, name, centre coordinates, radius
  universe.csv         the shared activity list (generated by build.py)
  geocode.csv          venue -> coordinates (Nominatim matches; generated by geocode.py)
  url_check.csv        HTTP status and "is the page about this?" per source link (generated by check_urls.py)
  osm_venues.csv       OpenStreetMap venue points for the map (sampled)
  osm_counts.csv       true OpenStreetMap venue counts per group
  osm_tags.json        activity id -> OpenStreetMap tag filters
  structural_ids.txt   activities bound to geography, climate or law
  SCHEMA.md            column definitions and rules
  RESEARCH_BRIEF.md    the brief given to research agents (definitions, evidence grading)
scripts/
  build.py             merge, dedupe, curate, geocode, tiers, validate -> ../assets/boring-cities/
  add_batch.py         add one research round's CSV to research.csv or not_found.csv
  gaps.py              what is still unresolved, per city or as a ranking of cities
  check_urls.py        are the source pages alive and about the activity?
  geocode.py           venue names -> coordinates via Nominatim (about 1 request a second)
  fetch_osm.py         venue counts and points from OpenStreetMap (slow; Overpass is flaky)
  fetch_wikipedia_seed.py   the Wikipedia pages the activity list was seeded from (one-off; output is git-ignored)
  report.py            coverage, cross-city comparison, the figures the post quotes, link/geocode review
  common.py            shared paths and table helpers
../assets/boring-cities/   the explorer: app.js, basemap.js, style.css, MapLibre files,
                           and the generated data.json, activities.csv, venues-<city>.json
```

## Add or refresh a city

```sh
# 1. add a row to data/cities.csv, then (optional, slow):
uv run scripts/fetch_osm.py <city>
# 2. research: see what is missing, give agents data/RESEARCH_BRIEF.md and the list, then add what they write
uv run scripts/gaps.py <city> --all --priority > gaps.csv
uv run scripts/add_batch.py <city> <batch> rows.csv                  # evidence rows
uv run scripts/add_batch.py <city> <batch> notfound.csv --not-found  # searched, nothing found
# 3. build and QA
uv run scripts/build.py
uv run scripts/check_urls.py <city>        # are the source pages alive and about the activity?
uv run scripts/geocode.py <city>
uv run scripts/report.py review <city>     # dead links, weak geocode matches
uv run scripts/build.py                    # again, to apply geocodes and link status
```

Other views: `gaps.py --waves` ranks cities by what is still unresolved, and `report.py coverage`,
`report.py compare [city ...]` and `report.py numbers [N]` summarise the built data.

## Method and honesty notes

- **Seeding.** Activities were drawn from independent lists (Wikipedia lists of sports, games,
  crafts, dance, collectables, plus hobby categories) plus brainstorming (`seed_source` says which).
  The list was assembled while researching Singapore first, so it can under-represent things only
  other cities have.
- **`doable`.** `yes` = the real thing exists within the metro area (~30 km of the centre);
  `partial` = a limited/simulated/indoor/informal version; `no` = structurally unavailable there
  (terrain, climate, law, animals). Never `no` merely because nothing was found.
- **Coverage is uneven, and that matters.** Singapore has all 299 activities researched; the other
  cities have fewer because web-search budget ran out repeatedly. A missing row means "not
  researched", never "no". Because the unresearched rows skew to niche items, cross-city comparisons
  use only activities researched in every chosen city.
- **Evidence.** Every `yes`/`partial` row has a `source_url`. `confidence` says how strong it is.
  `build.py` marks a row `verified` only if the link is alive, the page mentions the venue or
  the activity, and confidence is not `low`. The flag is in `data.json` (`verified`); the page
  doesn't expose it, but `report.py numbers` reports the share of rows that pass.
- **OpenStreetMap evidence** (rows in batch `osm`) = a named venue carries the matching tag within
  20 km of the centre. Medium confidence: tagged, not verified as currently operating.
- **Cost and distance** are tiers, not prices. Distance is recomputed from coordinates when known.
- **Map data.** Gray points are OpenStreetMap (ODbL), fetched once; they count venues, not quality,
  and counts depend on how thoroughly each city has been mapped.
- **Venue counts** (`osm_counts.csv`, within 25 km of the centre): Hong Kong, Tokyo and New York come
  from Overpass `out count` queries; London lacks "Arts & culture" and "Craft & maker" (those queries
  timed out); Singapore's "Sports facility" (4,515) and "Park & nature" (806) are from a fresh
  Overpass run that was stopped early, and its other groups were derived from the earlier full point
  set. Singapore's map points themselves come from that earlier fetch (island bounding box). Atlanta
  has counts for only three groups (parks, water and marina, arts and culture) with no map points:
  its Overpass run was stopped after hours of timeouts. The explorer no longer charts these counts;
  only the map points are used.
- **Layout history.** Research used to be stored as one CSV per round per city (about 230 files);
  they were merged into `research.csv` and `not_found.csv`, keeping each row's round in `batch`. The
  Wikipedia page dumps the list was seeded from are not stored; `fetch_wikipedia_seed.py` rebuilds them.
